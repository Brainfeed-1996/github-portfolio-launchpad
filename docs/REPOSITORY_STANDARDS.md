# Repository Standards

## Purpose

Every serious repository should look deliberate, production-minded, and complete.

## Required baseline

- LICENSE
- README.md
- CONTRIBUTING.md
- SECURITY.md
- CODE_OF_CONDUCT.md when community-facing
- docs/ directory for deep documentation
- examples/ when useful
- tests/
- CI workflow
- issue templates
- pull request template

## README structure

- title and one-line pitch
- why it exists
- capabilities
- architecture overview
- screenshots or diagrams when relevant
- quick start
- detailed setup
- configuration
- examples
- benchmarks or evaluation
- roadmap
- contribution guide
- license

## docs structure

- docs/architecture.md
- docs/design-decisions.md
- docs/threat-model.md when relevant
- docs/benchmarking.md
- docs/operations.md
- docs/roadmap.md
- docs/faq.md

## Engineering standards

- typed code where appropriate
- linters and formatters
- tests with clear strategy
- reproducible local setup
- sample data or fixtures
- real issue labels and milestones
- meaningful commit history

## Visual standards

- consistent badges, but not badge spam
- clean diagrams
- restrained, professional aesthetics
- strong naming and terminology consistency

## Recruiter-facing heuristic

A recruiter should understand in under 30 seconds:

- what the project does
- why it matters
- why it is hard
- what your contribution quality looks like
